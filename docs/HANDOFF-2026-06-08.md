### 3. Claim idempotency fix — `a62f7dd`

- **Bug**: labeler "claim failed" = backend 500 (`failed to claim item`, the default
  error branch). Prod log root cause: `Error 1062 Duplicate entry '<item>-<labeler>'
  for uk_item_labeler` at `claim.go` INSERT.
- **Cause**: `releaseExpiredClaims` returns an expired-claimed item to `available`
  but leaves its draft submission; the same labeler re-claiming that item then hit
  the unique key `(item_id, labeler_id)`.
- **Fix**: the new-claim path now calls `findOrCreateSubmission` (reuse the orphan
  draft) instead of a raw `tx.Create`, making claim idempotent. Regression test
  `TestClaim_ReusesExistingDraftSubmission`; existing claim sqlmock sequences updated
  for the extra `(item,labeler)` lookup.

## Deploy procedure

```bash
# from repo root, after committing
rsync -az -e "ssh -i ~/Downloads/labelhub.pem" apps/web/src/ \
  ubuntu@43.155.210.70:/home/ubuntu/labelhub/apps/web/src/
# backend changes also need:
rsync -az -e "ssh -i ~/Downloads/labelhub.pem" apps/api/internal/ \
  ubuntu@43.155.210.70:/home/ubuntu/labelhub/apps/api/internal/
ssh -i ~/Downloads/labelhub.pem ubuntu@43.155.210.70 \
  'cd /home/ubuntu/labelhub && docker compose --env-file deploy/.env \
   -f deploy/docker-compose.prod.yml up -d --build web api'
```

- SSH host alias `labelhub-prod` is in `~/.ssh/config` (ubuntu@43.155.210.70, key
  `~/Downloads/labelhub.pem`).
- The server-side `up -d --build` is the **real build verification** (local
  `vite build` OOM-kills on this Mac). If the build fails, the old containers keep
  running, so a broken build never takes the site down.
- `api` runs golang-migrate on startup; migration `016` is already applied.
