## OPEN BUG (the reason for this handoff — fix this next)

**Symptom (user report):** a labeler can keep re-claiming the same task. After claiming in 任务广场 the redirect to the answer view works, **but clicking 标注工作台 shows no task** — so the labeler goes back and re-claims.

**Root cause (frontend-confirmed):**
1. The labeler sidebar **3-way split** (`App.tsx`, introduced in `a8c5356`) gives `/labeler`, `/labeler/workbench`, `/labeler/mine` distinct route `key`s → `LabelerPlaza` **remounts fresh** on each. A task claimed in 任务广场 lives only in component state (`bundle` / `activeTask`), so the workbench remount (`initialView='answer'`) has no task → empty.
2. A freshly-claimed submission has status **`draft`**, and `MyData.bucketOf('draft')` returns **`null`** → the claimed-but-unsubmitted item is **invisible in 我的贡献 too**. So a "claimed, not yet submitted" item is unreachable anywhere except the original mount → the labeler re-claims.
3. **D (`1e64d27`) masks this**: empty workbench now falls back to 任务广场 instead of showing the dead-end — but it still doesn't resume the in-progress task.

**Proposed fix:**
- On workbench mount, **resume** the labeler's in-progress submission: after `loadMySubmissions`, if `initialView==='answer'` and nothing is active, `openSubmission(...)` the most-recent resumable submission; only fall back to the plaza (current D behavior) if there is genuinely none.
- Make the claimed `draft` **visible + clickable in `MyData`** (add a "进行中 / 待提交" bucket) so resume is also reachable from 我的贡献.
- Keep it **router-free**: `Plaza.test.tsx` renders `LabelerPlaza` **without a Router**, so do NOT use `useNavigate`/`<Navigate>`/`useLocation` (the existing split deliberately injects view via props + remount `key`, not router hooks).

**OPEN QUESTION (blocker for the exact fix — verify first):**
Does `GET /me/submissions` return `draft` (claimed-unsubmitted) submissions?
- Frontend loads it on mount (`Plaza.tsx` `loadMySubmissions` → `apiGet('/me/submissions')`). If it already includes drafts → the fix is **frontend-only** (resume + MyData bucket). If it filters drafts out → also need a backend change to include them (or add a "my current claim" source).
- Handler is in **`apps/api/internal/handler/labeler.go`** (also hosts `/labeler/tasks` and `/tasks/:id/claim`). Read it to confirm the status filter. (`submission`-claim status semantics: a claim creates a `draft` submission per the test fixtures; verify against the handler.)
